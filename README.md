# resume-tailor

按岗位 JD 定制简历的 Agent Skill。

不是模板填空工具。它的核心是**一份纯事实的经历库**：先通过追问把你做过的事挖成没有形容词的原子事实，之后每投一个岗位，对着那份 JD 重新挑选、组织、包装，输出可打印的 HTML。

一次建库，长期复用。

## 它解决什么

同一段经历对不同岗位是不同的侧面。「一个人跑通了商家入驻到售后」，投销售是拓客能力，投 FDE 是端到端交付，投电商是供应链。传统做法是维护三份简历，改一次经历要同步三处；这里只维护一份事实，简历是它对着某个 JD 的一次投影。

## 装

clone 进 Agent 的 skills 目录即可：

```bash
git clone https://github.com/JaelChen/resume-tailor.git ~/.claude/skills/resume-tailor
```

| Agent | 路径 |
| --- | --- |
| Claude Code | `~/.claude/skills/resume-tailor/` |
| Codex | `~/.codex/skills/resume-tailor/` |
| 通用 Agents | `~/.agents/skills/resume-tailor/` |
| 豆包 | 见其 Skill 安装说明，需专业版 |

Windows 上把 `~` 换成 `%USERPROFILE%`。豆包手机版可以直接说「安装这个 GitHub 仓库的 skill」。

读不了 skill 目录的环境，把 `SKILL.md` 全文粘进对话当提示词也能跑，只是没有自动触发。

## 用（照着走，别自己发挥）

说人话触发就行：「帮我改简历」「按这个岗位改简历」「帮我投这个 JD」。没触发就点名 `/resume-tailor`。

触发后它会先跟你讲清楚流程再开工。**不要跳过第一步直接让它做简历**——你随口说两句经历就要成品，出来的一定是没有事实支撑的套话，这个坑已经有人踩过了。

**第一步，把你现在的简历发给它。** 图片、PDF、Word、HTML 都行，直接拖进去。没有简历就说「我没有简历」，它会问你做过哪些事。

**第二步，回答它的追问。** 它会一件件问：你一个人做了哪部分、有没有数字、当时卡在哪、最后什么结果。大概二三十分钟。这是整个流程唯一花时间的地方，也是唯一别人替不了你的——经历库的质量决定后面所有简历的上限。你答「就是做了个电商项目」，它就只能写出「参与电商项目运营」。

答完你会得到一个 `经历库.md`，纯事实、长期保存，以后不用重来。

**第三步，之后每投一个岗位，发一张 JD 截图说「帮我投这个」。** 十分钟出结果：它拆出这份 JD 真正在买的能力点，从经历库挑证据，按简历该有的写法重组，给你带来源标记的草稿、命中计数、缺口清单。你审完确认，它直接出 HTML 和 PDF。

投递永远是你自己点的，它不会替你提交任何东西。

## 数据放哪

个人数据不进本目录，本目录只有逻辑，可以整个打包发人。

```
简历工作台/                     # Windows 默认 D:\简历工作台\，其他系统 ~/简历工作台/
  经历库.md                     # 纯事实，你的长期资产
  照片.jpg                      # 可选
  jobs/
    2026-09-05-公司-岗位/
      jd-01.png                # JD 原始截图，原样保留
      jd.md                    # 提取的文字 + 拆出的能力点
      简历.md                   # 带 [← 来源 | 相关度] 标记的草稿
      简历.html                 # 定稿
```

换电脑搬这个文件夹，skill 本身丢了随时能拷回来。

## 排版

`md2html.py` 零依赖，只用标准库。

```bash
python md2html.py 简历.md 简历.html --layout sidebar --photo 照片.jpg
```

| 参数 | 说明 |
| --- | --- |
| `--layout sidebar` | 满高彩色侧栏 + 照片 + 反白姓名（默认） |
| `--layout banner` | 顶部色块抬头 + 圆形照片 + 联系方式色带 + 双栏 |
| `--accent #1f3a5f` | 强调色 |
| `--photo 路径` | 内嵌证件照；不给则自动收掉照片位，不留空块 |
| `--keep-marks` | 保留来源标记，审草稿用；定稿不加 |

版式骨架参考了 [Reactive-Resume](https://github.com/AmruthPillai/Reactive-Resume) 的 gengar 与 leafish。

打印时在 Chrome 打印设置里**勾上「背景图形」**，否则侧栏色块全白；边距选「无」，边距已做在 CSS 里。

## 写法规则

条目按 Google XYZ 的三要素写——方法、成果、量化，缺一不可。但语序按中文来：**方法 → 成果与量化 → 判断**。英文的 `by doing Z` 是后置状语，中文的方法状语必须在动词前，照搬会得到翻译腔。

行首必须是实义动词。禁止「通过……」开头（状语顶到最前，第一个词不带信息），禁止「参与 / 负责 / 协助」开头（只证明在场，不证明有贡献），禁止给条目加自造的加粗小标题（用加粗伪造结构，也是 AI 味最重的写法）。

## 红线

数字不编、角色不升、没做的事不写、时间不拉长。

包装的合法范围是选择、命名、补口径——只讲和岗位相关的切面，换成对方语境里的说法，把已发生的事补全分母。宁可留白，宁可在缺口清单里如实标出来。越线的简历面试三个问题内就会穿帮。

追问阶段不质疑用户简历的真伪。追问细节本身就是筛子，答不出细节的条目自然进不了经历库。
